Se der certo, se der errado (&& e ||)

Às vezes você quer encadear dois pedidos na mesma linha: um depois do outro, ou o segundo só se o primeiro deu certo, ou só se o primeiro falhou. O Prompt usa &, && e || para isso, e guarda um código de saída no %errorlevel%. As respostas reais ainda estão a coletar.

Você vai aprender
  • O &, que roda o segundo comando sempre, tenha o primeiro dado certo ou não.
  • O &&, que só roda o segundo se o primeiro deu certo, e o ||, que só roda o segundo se o primeiro falhou.
  • O código de saída no %errorlevel% e o que acontece quando ele é lido na mesma linha (expansão antecipada): o lote 2b mostrou 0 e não imprimiu deu erro. Para ver o código novo na mesma linha, a outra coleta usa !errorlevel! com cmd /v:on.
Saídas desta aula. Parte das respostas do Prompt já veio do lote 2b, anonimizado em _saidas-anon/cmd-lote2b.txt. As demais caixas ainda mostram o placeholder « saída a coletar », até o restante da coleta entrar. Não complete as caixas de memória e não traduza mensagem de erro.

As saídas reais foram colhidas no Prompt de Comando de um Windows em português, na pasta de teste C:\Users\ana\guia-cmd-teste. No seu computador, pratique numa pasta de teste parecida, não na raiz do disco. O placeholder « saída a coletar » não é resposta do cmd; as caixas já preenchidas trazem a saída real, com a linha em branco que o Prompt deixa antes do próximo prompt.

A ideia: três tipos de “e depois”

O & é um “e também”, sem perguntar se o primeiro deu certo. O && é um “e, se deu certo, então…”. O || é um “ou, se deu errado, então…”. Os três não são o pipe |: o pipe passa a saída adiante; estes decidem se o próximo comando roda.

1. Sempre os dois: &

O echo da direita roda mesmo quando o type da esquerda encontra o arquivo, e também quando o arquivo não existe:

C:\Users\ana\guia-cmd-teste>type notas.txt & echo isto sempre roda

« saída a coletar »

C:\Users\ana\guia-cmd-teste>
C:\Users\ana\guia-cmd-teste>type arquivo-nao-existe.txt & echo isto sempre roda

« saída a coletar »

C:\Users\ana\guia-cmd-teste>
type notas.txt
o primeiro pedido.
&
“e também”, sempre.
echo isto sempre roda
o segundo pedido, que não depende do resultado do primeiro.

2. Só se der certo, só se der errado: && e ||

Com o dir de um arquivo que existe, o && deixa o echo rodar. Com um arquivo que não existe, o && segura o segundo pedido, e o || é quem fala:

C:\Users\ana\guia-cmd-teste>dir notas.txt >nul && echo notas.txt existe

« saída a coletar »

C:\Users\ana\guia-cmd-teste>
C:\Users\ana\guia-cmd-teste>dir arquivo-nao-existe.txt >nul 2>&1 && echo existe

« saída a coletar »

C:\Users\ana\guia-cmd-teste>
C:\Users\ana\guia-cmd-teste>dir arquivo-nao-existe.txt >nul 2>&1 || echo não existe

« saída a coletar »

C:\Users\ana\guia-cmd-teste>

O mesmo raciocínio vale para criar pastas, só dentro da pasta de teste. O md projetos cria uma pasta nova; o md fotos tenta criar uma pasta que a semente já deixou lá:

C:\Users\ana\guia-cmd-teste>md projetos && echo pasta criada

« saída a coletar »

C:\Users\ana\guia-cmd-teste>
C:\Users\ana\guia-cmd-teste>md fotos || echo não deu para criar

« saída a coletar »

C:\Users\ana\guia-cmd-teste>

Na mesma linha, && e || também se combinam: “se achei, diga achei; senão, diga não achei”.

C:\Users\ana\guia-cmd-teste>dir notas.txt >nul 2>&1 && echo achei || echo não achei

« saída a coletar »

C:\Users\ana\guia-cmd-teste>
C:\Users\ana\guia-cmd-teste>dir nada.txt >nul 2>&1 && echo achei || echo não achei

« saída a coletar »

C:\Users\ana\guia-cmd-teste>

3. O código de saída: %errorlevel% e !errorlevel!

Depois de cada comando, o Prompt guarda um número: zero costuma significar “deu certo”; outro valor, “deu errado”. Esse número é o %errorlevel%.

Na mesma linha, porém, o Prompt expande o %errorlevel% antes de rodar o dir. O lote 2b coletou isso com um arquivo que não existe. A mensagem Arquivo não encontrado apareceu, mas o echo %errorlevel% imprimiu 0 — o código antigo, de um comando que tinha dado certo, não o código novo do dir:

C:\Users\ana\guia-cmd-teste>dir nao-existe.txt & echo %errorlevel%
 O volume na unidade C não tem nome.
 O Número de Série do Volume é XXXX-XXXX

 Pasta de C:\Users\ana\guia-cmd-teste

Arquivo não encontrado
0

C:\Users\ana\guia-cmd-teste>

O mesmo vale para o if %errorlevel% NEQ 0 na mesma linha: o teste usou o valor velho (zero), então a frase deu erro não foi impressa. Só o cabeçalho do dir e o Arquivo não encontrado apareceram:

C:\Users\ana\guia-cmd-teste>dir nao-existe.txt & if %errorlevel% NEQ 0 echo deu erro
 O volume na unidade C não tem nome.
 O Número de Série do Volume é XXXX-XXXX

 Pasta de C:\Users\ana\guia-cmd-teste

Arquivo não encontrado

C:\Users\ana\guia-cmd-teste>
Expansão antecipada

Tudo o que está entre % e % numa linha é trocado pelo valor atual antes de a linha começar a rodar. Por isso %errorlevel% na mesma linha do comando que acabou de falhar ainda mostra o código anterior. Para ler o código novo na mesma linha, a outra coleta ligou a expansão atrasada (cmd /v:on) e usou !errorlevel!. Essas caixas ainda estão a completar:

C:\Users\ana\guia-cmd-teste>dir notas.txt >nul & echo errorlevel: !errorlevel!

« saída a coletar »

C:\Users\ana\guia-cmd-teste>
C:\Users\ana\guia-cmd-teste>dir nada.txt >nul 2>&1 & echo errorlevel: !errorlevel!

« saída a coletar »

C:\Users\ana\guia-cmd-teste>

4. Dois ecos no mesmo arquivo

Os parênteses juntam dois echo ligados por &, e o > manda os dois para o mesmo arquivo. O type mostra o que ficou gravado:

C:\Users\ana\guia-cmd-teste>(echo um & echo dois) > duas-linhas.txt

« saída a coletar »

C:\Users\ana\guia-cmd-teste>
C:\Users\ana\guia-cmd-teste>type duas-linhas.txt

« saída a coletar »

C:\Users\ana\guia-cmd-teste>

Formas diferentes de encadear

FormaQuando usar
comando1 & comando2Para rodar os dois, sempre.
comando1 && comando2Para rodar o segundo só se o primeiro deu certo.
comando1 || comando2Para rodar o segundo só se o primeiro falhou.
comando1 && eco1 || eco2Para dizer uma coisa se deu certo e outra se deu errado.
echo %errorlevel% na mesma linhaExpande o valor antes do comando: no lote 2b saiu 0, mesmo depois de um dir que falhou.
echo errorlevel: !errorlevel!Para ver o código novo na mesma linha, com cmd /v:on.

Quando dá errado

Um arquivo que não existe, com & e com ||

Os pedidos com arquivo-nao-existe.txt e nada.txt já estão nas seções acima. A mensagem de erro real — e o fato de o segundo comando rodar ou não — só entra quando a coleta for anonimizada. Não traduzimos a frase do Windows.

Referência rápida

Você digitaO que faz
&Roda o próximo comando sempre.
&&Roda o próximo só se o anterior deu certo.
||Roda o próximo só se o anterior falhou.
%errorlevel% / !errorlevel!O código de saída. Na mesma linha, %errorlevel% ainda tem o valor antigo; !errorlevel! (com /v:on) lê o valor novo.

Resumo

  • & roda os dois sempre; && roda o segundo só se o primeiro deu certo; || só se o primeiro falhou.
  • Isso não é o pipe |: aqui a decisão é “roda ou não”, não “passa a saída adiante”.
  • O código de saída fica no %errorlevel%. Na mesma linha, a expansão é antecipada: o lote 2b mostrou 0 e o if %errorlevel% NEQ 0 não imprimiu deu erro. O !errorlevel! (com /v:on) lê o valor novo.
